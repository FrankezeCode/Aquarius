## Overview

The Aquarius API is the primary interface for consuming risk intelligence. It is built on Fastify and versioned under `/v1/`. All endpoints are read-only, schema-validated, and designed for programmatic consumption by bots, dashboards, and protocol integrations.

<Callout type="info" title="API-First Design">
The API is the product. The web frontend, SDK, and all internal services consume the same API endpoints. There is no privileged internal access.
</Callout>

## Base URL

```
https://api.aquarius.finance/v1
```

## Authentication

Public risk endpoints do not require authentication in the current release. Rate limiting is enforced per IP address.

| Tier | Rate Limit |
|---|---|
| Public | 60 requests/minute |
| Authenticated (future) | 600 requests/minute |
| Enterprise (future) | Custom |

**Path Parameters**

| Parameter | Type | Description |

    "slope": -0.0013,
    "isAccelerating": true
  },

**Response Schema**

| Field | Type | Description |
|---|---|---|
| `user` | `string` | User address |
| `currentHF` | `number` | Current health factor |
| `projectedHF` | `number` | Projected health factor at `blocksAhead` |

## Agent Enrollment (Phase A + Phase B Hard-Fail)

Agent enrollment supports a phased lifecycle:

- **Phase A**: off-chain enrollment save (`pending_onchain`)
- **Phase B**: strict on-chain wallet bind/deactivate on Tenderly (`bind-intent` + `confirm-bind`, `deactivate-intent` + `confirm-deactivate`)
- Persistence now: in-memory (prototype validation; resets on API restart)
- Channels now: Telegram mandatory (non-strict), Webhook optional

### Wallet + Tenderly prerequisites

- A real EVM wallet (MetaMask) must be connected in the web app on a supported chain (`ethereum`, `polygon`).
- Tenderly RPC must be configured for the active chain via `TENDERLY_RPC_URL` / `TENDERLY_RPC_URL_*` (server) and `NEXT_PUBLIC_TENDERLY_RPC_URL` / `NEXT_PUBLIC_TENDERLY_RPC_URL_*` (web). Without these, Tenderly-backed endpoints and simulations may return `503`.

### Phase A vs Phase B policy flow

- **Phase A**: `/v1/agent-enrollment` saves enrollment draft only (no tx required).
- **Phase B hard-fail**: activation/deactivation require MetaMask tx and finalize only after confirm endpoints succeed.

### Binding lifecycle fields (additive, backward compatible)

- `policyBindingStatus`: `pending_onchain | signing_requested | pending_tx | bound_onchain | bind_failed`
- `policyBindingRef`: `string | null` (tx hash / reference)
- `bindingChainId`: `number | null`
- `bindingError`: `string | null`
- `lastBindingAttemptAt`: `number | null`
- `lastBindingIdempotencyKey`: `string | null`
- `status`: `active | inactive`
- `deactivationTxRef`: `string | null`
- `deactivatedAt`: `number | null`
- `deactivationError`: `string | null`
- `lastDeactivationAttemptAt`: `number | null`
